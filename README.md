# OpsDesk · 桌面端个人工作台

面向程序员 / 技术骨干的单页应用（SPA）。**零后端、零运行时依赖**，所有数据通过浏览器 `localStorage` + `IndexedDB` 双写持久化，刷新与重启浏览器绝不丢失。

---

## 快速开始

### 方式一：一键启动（推荐日常使用）

- **macOS / Linux / 麒麟 / UOS**：双击 `启动.command`（麒麟建议在终端执行 `./启动.command`，或用 `OpsDesk.desktop` 建桌面快捷方式）
- **Windows**：双击 `start.bat`

自动起本地服务并打开浏览器，**无需安装任何东西**（缺 Python 时会自动退回「直接打开文件」模式）。

> 国产系统与 ARM 架构（麒麟、统信、飞腾、鲲鹏、龙芯）**开箱即用**：
> 应用是纯 HTML/CSS/JS，不含本地二进制依赖，CSS 已预先编译，运行时不依赖 Node.js。

### 方式二：直接打开文件

```
双击 index.html
```

全部资源均为本地相对路径，Tailwind 已编译进 `assets/css/app.css`，**无需构建、无需联网、无需起服务**。

> ⚠️ `file://` 与 `http://localhost:5173` 在浏览器里是**两个互相隔离的存储空间**，数据不互通。
> 请固定用一种方式，不要两边都录入数据。

### 方式三：开发模式

```bash
npm install          # 仅首次需要（仅装 tailwindcss 用于改样式）
npm run serve        # http://localhost:5173
```

### 修改样式后重新编译 Tailwind

```bash
npm run build:css    # 产物写入 assets/css/app.css
npm run watch:css    # 开发时自动编译
```

### 部署到其他电脑

见 **[部署说明.md](./部署说明.md)**：程序文件直接拷贝，数据用左栏「导出备份 / 导入备份」迁移。

## 四大核心模块 + 版本投产台账

### ① 日程与任务管理（`tasks.js`）

| 能力 | 说明 |
|---|---|
| **工作时间必填** | 未填写开始/结束时间**无法保存**，字段红框高亮 + 红色提示 + Toast 拦截；同时校验「结束时间须晚于开始时间」 |
| 任务属性 | 名称、预计时间段、状态（待办/进行中/已完成/阻塞）、优先级（P0–P3）、所属项目、备注、**长线标记** |
| 时间轴 | 按日渲染 07:00–22:00 时间线，**重叠任务自动分泳道并排**，含当前时间指示线 |
| 看板拖拽 | 四状态看板，卡片可拖拽跨列切换状态；也可单击卡片循环流转状态 |
| 筛选 | 日期前后翻页、项目筛选、状态筛选、关键词搜索；**筛选结果同时作用于统计条、时间轴与看板三处**，并在时间线标题显示「已筛选 / 共 N 项」；筛空时提供「清除筛选条件」快捷入口 |

### 日期 / 时间选择控件（`picker.js`）

任务的日期与开始/结束时间、故障的发生日期与发生时间、流水账的日期与起止时间，**全部改为点选控件，不再需要手输**。

| 控件 | 能力 |
|---|---|
| 日期面板 | 月份网格（周日开头）、‹ / › 翻月、**今日高亮**、选中高亮、非本月淡显；快捷「昨天 / 今天 / 明天」；底部保留手动输入兜底（YYYY-MM-DD） |
| 时间面板 | 16 个**常用时段**快捷（08:30 … 21:00）、小时 00–23 与分钟 00–55（步长 5）两段式选择、「清空」、底部手动输入兜底（HH:MM）+「确定」 |
| 相对快捷 | **结束时间**面板顶部提供「基于开始时间」的 +30 分 / +1 小时 / +1.5 小时 / +2 小时 / +半天，一键推导结束时刻 |
| 交互细节 | 浮层挂在 `document.body`（不被弹窗滚动区裁剪）、空间不足自动翻到上方；点击外部 / 滚动 / 缩放自动收起或重定位；**Esc 只关闭选择面板**，不会连带关掉外层弹窗 |

实现上采用「**隐藏原生 `input[type=date|time]` 作数据载体 + 可见按钮触发自绘面板**」：既拿到点选体验，又完整保留既有的取值、必填校验、标红逻辑，对存量代码与测试零回归。

### ② 项目管理（`projects.js`）

侧栏「数据管理 → 项目管理」进入，或点总览页「重点项目与长线推进 / 项目负载」面板的**管理**按钮。

| 能力 | 说明 |
|---|---|
| 重点项目标记 | 每个项目有「★ 重点」开关，点击即可切换；重点项目会进入晨会站会稿的「重点项目」段落 |
| 删除项目 | 删项目时若其下有任务 / 故障 / 流水，会**要求先选择迁移目标**，记录不会静默丢失；也可选择「一并删除这些记录」 |
| 新建 / 编辑 | 名称、说明、标识颜色、重点标记，名称重名会拦截 |
| 兜底 | 至少保留一个项目，最后一个项目的删除按钮为禁用态 |

**长线任务**通过任务编辑弹窗里的「标记为长线推进」勾选框开关，取消勾选即从长线事项中移除。

### ④ 「重点项目与长线推进」面板的口径

总览页的这个面板把三类「重点」**分开分组并标注入选原因**，避免混淆：

| 分组 | 入选条件 | 条目右上角标记 |
|---|---|---|
| **重点项目** | 项目被标记为「重点」 | `重点`（项目名 + 在推进项数） |
| **长线推进** | 任务勾选了「标记为长线推进」 | `长线` |
| **P0 进行中** | 任务优先级 P0 且状态为进行中（**与长线标记无关**） | `P0` |

> ⚠️ 一个任务即使取消长线标记，只要它是 **P0 + 进行中**，仍会出现在「P0 进行中」分组里 ——
> 这是有意为之（P0 在办的事站会上必须讲），但它已**不再计入长线**，标记也会明确显示为 `P0`。
> 任务标题里的「【长线】」只是普通文本，与长线标记无关，取消标记不会自动改标题。

### ③ 所属项目字段可内联维护

新建 / 编辑**任务**、**生产问题**、**时间流水**时，「所属项目」不只是下拉框，下方还有一排维护按钮：

| 按钮 | 作用 |
|---|---|
| **＋ 新建** | 就地新建项目（名称 / 说明 / 颜色 / 重点标记），保存后**立即出现在下拉里并被选中** |
| **✎ 重命名** | 编辑当前选中的项目；改名后**所有历史记录同步显示新名字**（记录只存项目 ID，不存名字） |
| **🗑 删除** | 删除当前选中的项目；若其下有任务 / 故障 / 流水，会先要求选择迁移目标，记录不会静默丢失 |

下拉右侧还会实时显示当前项目的说明与关联记录条数。**项目改名、删除在任意一个表单里操作，其它视图立刻同步**，不必跳转到项目管理面板。

### ② 生产问题排查看板（`incidents.js`）

结构化录入四个核心字段：**故障/现象**、**影响范围**、**排查与定位过程**、**解决方案/状态**，另含严重级别、项目、发生时间与负责人。
支持按**状态**（已解决 / 跟进中，带计数）、**时间**（正/倒序）、项目与全文关键词检索，便于复盘。

### ③ 时间分配流水账（`timelog.js`）

- 极简打卡：快速输入 `14:00-16:00 编写 Spark 脚本` 即可入库
- **自动计算时长**并**自动归类**（开发 / 运维 / 会议 / 排错，基于描述关键词推断，可手动覆盖）
- 当日**环形图 + 分类占比条**双重视觉化

### ⑤ 版本投产台账（`releases.js`）

按**版本**归档上线内容，随时回看「这一版到底投了什么、是谁做的」。侧栏第 5 项或按 `5` 进入，顶栏「⧉ 投产」按钮可快速新建。

**版本层字段**：版本号\*（唯一）、版本名称、上线日期\*、上线状态（待上线 / 已上线 / 已回滚）、发布负责人、备注。

**投产内容层字段**（一个版本下可挂多条）：

| 字段 | 说明 |
|---|---|
| 内容类型\* | ✨ **业务需求** / ⚙️ **技术优化** / 🐛 **缺陷修复** / 📦 其他变更 |
| 内容标题\* | 这一条具体做了什么 |
| 开发人\* | **必填**，用于追溯「谁产出了什么」；可按开发人搜索 |
| 说明 | 影响范围、验证方式、回归结论等 |

| 能力 | 说明 |
|---|---|
| 类型分组展示 | 版本卡片内按**类型分组**，每组带条数小标题，一眼看清这版的构成 |
| 筛选 | 状态筛选 + 类型筛选 + 关键词搜索（命中版本号 / 内容 / 开发人），三者可叠加 |
| 分布统计 | 侧栏「投产内容分布」：按类型的占比条 + 按开发人的产出条数 |
| 快捷操作 | 卡片内「⧉ 复制为新版本」（带出原有投产内容，版本号留空待填）、「✎ 编辑」、「🗑 删除」 |
| 逐条维护 | 已保存版本上可直接「＋ 添加投产内容」，点击任意条目即可编辑或删除 |
| 总览联动 | 总览页新增「近期版本投产」面板，右栏在版本视图下输出投产摘要 |

### ④ 智能晨会汇报生成器（`briefing.js`）

晨会是**站会形式，1-2 分钟**，因此生成的是「站会稿」——**每条一行、只讲结论、不展开明细**，超出容量的条目折叠提示，明细回源到对应模块查看。

一键「生成站会稿」，自动聚合：

1. 📝 **昨日产出** — 昨日至今已完成的任务，带项目归属
2. 🚨 **生产问题** — 近 7 天故障，**跟进中的优先保留**并附一句进展，已解决的一句话带过
3. 🎯 **重点项目** — 旗舰项目与长线任务的里程碑进展
4. 📅 **今日计划** — 阻塞项置顶报警，随后是今日/明日排期（含时间段、优先级）

稿尾带**口播时长自检**（按中文约 4.5 字/秒估算），超过 2 分钟会标 ⚠️ 提示精简；右栏同步显示各段数据量与口播时长。输出为可直接粘贴进群的 Markdown，支持**一键复制到剪贴板**与**导出 .md 文件**。

## 单元测试

测试基于 **Node 内置 `node:test` + jsdom**，不引入 Jest / Mocha 等重框架；应用源码零改动即可被测试。

```bash
npm install          # 安装测试依赖：jsdom、fake-indexeddb
npm test             # 运行全部测试（155 项，约 3.7s）
npm run test:watch   # 监听模式
```

`test/harness.js` 负责构建浏览器环境：

- 用 jsdom 渲染与 `index.html` 等价的骨架，按依赖顺序 `win.eval()` 加载 15 个脚本
- 注入 `fake-indexeddb`（IndexedDB 镜像存储）、`clipboard`、`URL.createObjectURL`、`getBoundingClientRect` 稳定默认值
- 接管 `setInterval / setTimeout`，测试结束后统一清理，避免 Node 进程无法退出
- 通过 `document.body[data-opsdesk-manual="1"]` 阻止 `app.js` 自动启动，改由测试显式调用 `App.boot()` 并 `await App.ready`

覆盖范围包括**工作时间必填校验**（全空 / 漏填结束 / 名称为空 / 结束早于开始 / 起止相同均拦截且弹窗不关闭）、localStorage 与 IndexedDB 双写与恢复、时长统计口径一致性、时间轴泳道布局、看板拖拽与筛选同步、**站会稿的精简度与口播时长预算**、**长线标记开关与项目删除的记录迁移**、**项目选择器的内联新建/重命名/删除与实时同步**、**数据变更后视图自动刷新**、**日期/时间选择控件的点选与联动**（日期网格、常用时段、相对开始时间推导、手动输入兜底、Esc 只关面板、清空时间后必填拦截）、**版本投产台账**（类型字典、脏数据归一化、统计口径、版本号唯一与必填拦截、条目开发人必填、状态/类型/关键词筛选、删除与复制、备份包含版本）、晨会简报四段结构与 XSS 防护、路由与快捷键、主题持久化、环形图与占比条渲染。

## 数据持久化

`storage.js` 实现**双写互备**策略：

- **localStorage**（主存储）：同步写入，读取快；附带 `meta.updatedAt` 时间戳
- **IndexedDB**（镜像备份）：异步写入 `opsdesk-db / kv / state`
- **启动恢复**：比对两侧时间戳，取较新的一份，并立即回填较旧的一侧 —— 即使其中一侧被浏览器清理，数据仍可从另一侧完整恢复
- **写入时机**：每次变更 120ms 防抖落盘；页面关闭前 (`beforeunload`) 与标签页隐藏时 (`visibilitychange`) 强制落盘
- **数据安全**：所有用户输入渲染前经 `U.esc()` 转义；导入数据经 `normalize()` 校验修复

### ⚠️ 数据不入库：仓库里只有演示数据

本仓库（GitHub）**不包含任何真实工作数据**。

- 所有业务数据（任务 / 故障 / 流水 / 项目 / 版本投产）**只存在于你自己的浏览器**（localStorage + IndexedDB），代码里写不进去，仓库里也就没有
- 仓库中唯一的数据是 `src/js/seed.js` 里的**内置演示种子数据**（首次打开时灌入，用于体验功能），全部为虚构内容
- `.gitignore` 已显式排除 `opsdesk-backup-*.json`、`*backup*.json`、`data/`、`.env*` 等，避免导出的真实数据被误提交
- **向仓库提交代码前，务必确认工作目录里没有导出的 JSON 备份**；需要演示数据时用「重置演示数据」生成，而不是把真实备份拷进工程目录

### 导入 / 导出

左栏「数据管理」提供 JSON 备份导出、导入、以及重置为演示数据。

> ⚠️ **「重置演示数据」会清空全部本地数据**（任务、故障、流水、项目、版本投产）并重新灌入内置的演示数据。
> 正式使用后请谨慎点击，只想看功能演示时才用。日常备份建议：每周点一次「导出备份」，把 JSON 存到网盘或 GitHub。

### 数据变更后的界面刷新

任何数据变更（新建 / 编辑 / 删除任务、故障、流水，增删改项目、切换状态、拖拽改状态）后，**当前视图会自动重绘**。这条由 `app.js` 对 store 的订阅统一保证，各模块无需手动调 `render()`，因此不会出现「数据存进去了但界面还是旧的」。

搜索框输入走的是独立通路（防抖后重绘），不受影响。

## 浏览器兼容

Chrome / Edge / Firefox / Safari 最新版。使用了 `backdrop-filter`、CSS Grid、CSS 变量等现代特性。

## 技术栈

- **Tailwind CSS 3.4**（本地编译，产物已提交，运行时不依赖 CDN）
- **原生 JavaScript**（无框架、无打包器、无运行时依赖）
- **SVG 手写图表**（环形图 / 占比条），无图表库
- **localStorage + IndexedDB** 双写持久化
